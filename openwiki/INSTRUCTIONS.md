# OpenWiki Instructions

This directory is an evidence index generated by [OpenWiki](https://github.com/earendil-works/openwiki). It is written in English and grounded in source code, not in the Portuguese wiki under `docs/`.

## Page types

### Generated pages
A page is generated when its front matter contains a `verified:` block, for example:

```yaml
verified:
  - by: openwiki/0.7.2
    at: 2026-10-16T16:12:57.544Z
```

Rules:
- Do not edit a generated page by hand. Change the source code or the docs and let OpenWiki regenerate it.
- If a factual error must be fixed before the next regeneration, change only the affected prose and then update the matching `statement` in `openwiki/.claims/<page>.json`.
- Never modify an `evidence.version` string: it is a resolver-owned token that OpenWiki computes from the source. Editing it breaks verification.
- Never add a new claim by hand with a made-up evidence version. New claims come from regeneration.

### Hand-written pages
Quickstart, the security model, the instructions page, and any page added manually carry front matter fields but no `verified:` block:

```yaml
---
type: architecture
title: Error Handling
description: ...
tags: [lua, errors]
---
```

Rules:
- Hand-written pages are edited directly.
- A new section added by hand to a generated page has no claim until the next `openwiki code --update` run; do not invent a claim or an evidence version for it.
- They have no Claims sidecar and are not listed in `.page-manifest.json`.
- Keep claims about behavior grounded in `src/` and `tests/`; cite file paths, not line numbers, because line numbers drift.

## Claims sidecars

Every generated page has a sidecar at `openwiki/.claims/<path>.json`:

```json
{
  "schemaVersion": 1,
  "pageVersion": "sha256:...",
  "claims": [
    {
      "id": "claim_<hex>",
      "statement": "One atomic factual proposition.",
      "evidence": [
        {
          "resource": "repo://src/router.lua#L46-L69",
          "version": "repo-lines-v1:sha256:..."
        }
      ]
    }
  ]
}
```

- `statement` must be one atomic, verifiable claim.
- `evidence` points at a stable source identity plus a resolver-owned version token.
- `.page-manifest.json` and `.last-update.json` are generated; do not hand-edit them.
- Validate any touched JSON: `jq . <file> >/dev/null`.

## Updating the wiki

```bash
npx -y openwiki@0.7.2 code --update
```

- Requires a provider key (`GEMINI_API_KEY` for the configured Gemini provider) for real regeneration.
- Never run `openwiki init` again on this repository: it would overwrite the index and the claims.
- The scheduled workflow `.github/workflows/openwiki-update.yml` runs the update daily. It uses the Gemini (Google AI Studio) provider and needs the `GEMINI_API_KEY` repository secret; without it the run fails.

## Review checklist

- [ ] Generated pages were not hand-edited (or the matching claim `statement` was updated).
- [ ] No `evidence.version` was changed.
- [ ] Hand-written pages keep `type`, `title`, `description`, and `tags`, and have no `verified:` block.
- [ ] JSON sidecars pass `jq .`.
- [ ] Statements match `src/` and `tests/`, including test counts and phase numbers.
- [ ] No placeholder or legacy project names remain.
